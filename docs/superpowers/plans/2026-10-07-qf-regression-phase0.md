# QF Regression Harness (Phase 0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the regression safety net (real-SQLite test harness, characterization tests, golden databases from the shipped release, upgrade-path migration tests, backend/mobile contract fixtures, a native Android build in CI, and Argent baseline flows) before any QF content-sync mobile code is written.

**Architecture:** A test-only `expo-sqlite` adapter backed by `better-sqlite3` lets Jest run the app's real database services against real SQLite files. Golden databases are produced by running the **release** (`v2.3.0`, `v2.2.1`) database services through that adapter and committed as fixtures; every later migration is tested against copies of them. Contract fixtures generated by the backend are mirrored into the mobile repo. Argent records baseline device flows for later replay.

**Tech Stack:** Jest (`jest-expo` preset), `better-sqlite3` (dev dependency, Node only), Bun tests in the backend, GitHub Actions, Argent MCP (local simulators/emulators).

**Spec:** `docs/superpowers/specs/2026-10-07-qf-regression-testing-strategy.md` (layers 1, 2, 3, 5, 6). Related: `docs/superpowers/specs/2026-10-05-content-freshness-qf-sync-design.md`.

**Repos / branches:**

- Backend (Task 6 only): `thebayaan/bayaan-backend`, existing branch `feat/content-sync` (PR #25), worktree `~/orca/workspaces/Bayaan/bayaan-backend-content-sync`.

## Global Constraints

- `better-sqlite3` is a **devDependency** only; nothing under `app/`, `components/`, `services/`, `store/`, `utils/` may import it or the adapter. The adapter lives in `test-utils/`.
- No QF content is committed: golden databases replace tafsir and translation text with short synthetic strings; contract fixtures use synthetic text in QF's real record shape (QF terms: no caching beyond a week, no prepackaged QF content).
- Golden fixture files live in `test-fixtures/golden/<tag>/` (`verse-annotations.db`, `playlists.db`, `tafaseer.db`, `translations.db`, `adhkar.db` when feasible) with a `manifest.json` describing the data seeded.
- Golden data must include every rewayah id form ever written: canonical (`hafs`, `warsh`, `shubah`, `al-bazzi`, `qunbul`, `qalun`, `al-duri-abi-amr`, `al-susi`) and legacy (`shouba`, `bazzi`, `qumbul`, `qaloon`, `doori`, `soosi`), plus `NULL` where the schema allows it.
- Tests must not touch the network except the opt-in Ibn Kathir parity fetch (Task 5), which is skipped unless `QF_PARITY_SNAPSHOT` points at a local file.
- TypeScript strict, no `any`; `as` only at the adapter's SQLite boundary. `function` keyword for pure helpers. No em dashes anywhere. Prettier on changed mobile files (`npx prettier --write`), `npx tsc --noEmit`, `npx jest` green before each commit.
- Commits: conventional, trailer `Co-Authored-By: Claude <model> <noreply@anthropic.com>`. Never push; the controller pushes after the final review.

## Review Focus

1. **The adapter silently differs from expo-sqlite semantics** (parameter binding forms, `runAsync` result shape, nested `withTransactionAsync`, `execAsync` with multiple statements). Expected: the adapter's own tests pin each behavior the app relies on, so a migration test cannot pass only because the adapter is more lenient than the device. Task 1.
2. **Golden databases do not reflect real devices** (generated by code, not captured). Expected: one schema-level comparison against a database pulled from a real simulator running `v2.3.0` (Task 8) passes; any difference fails loudly. Task 8.
3. **A golden database opened by today's `develop` code loses or rewrites data** (develop is 126 commits ahead of `v2.3.0`). Expected: the upgrade test reports exact per-table counts and field equality, and fails on any loss. Task 4.
4. **Contract fixtures drift silently** (backend changes the manifest shape and nobody updates mobile). Expected: the backend test fails until fixtures are regenerated, and the mobile check script shows the diff. Task 6.
5. **The Android build breaks only in CI conditions** (no signing keys, no Sentry auth token). Expected: the workflow builds `assembleDebug` without secrets. Task 7.

`test-utils/sqliteAdapter.ts`:

```ts
import Database from 'better-sqlite3';

export type SqlValue = string | number | null | boolean | Uint8Array;
export type SqlParams = [] | [SqlValue[]] | [Record<string, SqlValue>] | SqlValue[];

export interface AdapterDatabase {
  execAsync(source: string): Promise<void>;
  runAsync(source: string, ...params: SqlParams): Promise<{lastInsertRowId: number; changes: number}>;
  getAllAsync<T>(source: string, ...params: SqlParams): Promise<T[]>;
  getFirstAsync<T>(source: string, ...params: SqlParams): Promise<T | null>;
  withTransactionAsync(task: () => Promise<void>): Promise<void>;
  closeAsync(): Promise<void>;
}

type Bindable = string | number | bigint | null | Buffer;

function toBindable(value: SqlValue): Bindable {
  if (typeof value === 'boolean') return value ? 1 : 0;
  if (value instanceof Uint8Array) return Buffer.from(value);
  return value;
}

// expo-sqlite accepts (sql, [a, b]), (sql, a, b) or (sql, {$name: v}).
function normalize(params: SqlParams): Bindable[] | Record<string, Bindable> {
  if (params.length === 1 && Array.isArray(params[0])) return params[0].map(toBindable);
  if (params.length === 1 && params[0] !== null && typeof params[0] === 'object' && !(params[0] instanceof Uint8Array)) {
    const named: Record<string, Bindable> = {};
    for (const [key, value] of Object.entries(params[0])) named[key.replace(/^[$:@]/, '')] = toBindable(value);
    return named;
  }
  return (params as SqlValue[]).map(toBindable);
}

export function openAdapterDatabase(filePath: string): AdapterDatabase {
  const db = new Database(filePath);
  let depth = 0;
  return {
    async execAsync(source) {
      db.exec(source);
    },
    async runAsync(source, ...params) {
      const info = db.prepare(source).run(normalize(params));
      return {lastInsertRowId: Number(info.lastInsertRowid), changes: info.changes};
    },
    async getAllAsync<T>(source: string, ...params: SqlParams) {
      return db.prepare(source).all(normalize(params)) as T[];
    },
    async getFirstAsync<T>(source: string, ...params: SqlParams) {
      const row = db.prepare(source).get(normalize(params));
      return (row ?? null) as T | null;
    },
    async withTransactionAsync(task) {
      // expo-sqlite runs the task inside BEGIN/COMMIT; nested calls join the outer transaction.
      if (depth > 0) {
        await task();
        return;
      }
      depth++;
      db.exec('BEGIN');
      try {
        await task();
        db.exec('COMMIT');
      } catch (error) {
        db.exec('ROLLBACK');
        throw error;
      } finally {
        depth--;
      }
    },
    async closeAsync() {
      db.close();
    },
  };
}
```

import fs from 'fs';
import os from 'os';
import path from 'path';
import {openAdapterDatabase, type AdapterDatabase} from './sqliteAdapter';

let currentDir = fs.mkdtempSync(path.join(os.tmpdir(), 'expo-sqlite-'));
const open = new Map<string, AdapterDatabase>();

export function databaseDir(): string {
  return currentDir;
}

// Called in beforeEach for isolation; closes handles and starts a new directory.
export async function resetDatabases(): Promise<void> {
  for (const db of open.values()) await db.closeAsync();
  open.clear();
  currentDir = fs.mkdtempSync(path.join(os.tmpdir(), 'expo-sqlite-'));
}

export const expoSqliteModule = {
  openDatabaseAsync: async (name: string) => {
    const existing = open.get(name);
    if (existing) return existing;
    const db = openAdapterDatabase(path.join(currentDir, name));
    open.set(name, db);
    return db;
  },
};

# Generate golden SQLite databases by running the RELEASE database services

TAG="${1:?usage: generate.sh <tag>}"
ROOT="$(git rev-parse --show-toplevel)"
WORK="$(mktemp -d)/release"
OUT="$ROOT/test-fixtures/golden/$TAG"

git -C "$ROOT" worktree add --detach "$WORK" "$TAG" >/dev/null
trap 'git -C "$ROOT" worktree remove --force "$WORK" >/dev/null 2>&1 || true' EXIT

mkdir -p "$OUT"
rm -f "$OUT"/*.db "$OUT/manifest.json"
GOLDEN_RELEASE_ROOT="$WORK" GOLDEN_OUT="$OUT" GOLDEN_TAG="$TAG" \
  GOLDEN_COMMIT="$(git -C "$ROOT" rev-parse "$TAG")" \
